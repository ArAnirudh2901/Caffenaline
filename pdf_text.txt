1. Executive Introduction and Conceptual Paradigm 
The digital landscape of frontend development in 2026 demands unprecedented levels of 
interactivity, spatial storytelling, and fluid performance. Modern web experiences have evolved 
far beyond static two-dimensional pages, transitioning into immersive three-dimensional 
environments that leverage the full computational power of the user's graphical processing 
unit through WebGL and WebGPU APIs. For a brand conceptualized as "Caffenaline"—a 
high-energy, adrenaline-focused coffee purveyor operating under the tagline "Adrenaline 
rushes for coffee"—the digital presence must reflect the intense, stimulating nature of the 
product itself. The brand's core positioning demands a departure from the traditional, rustic, 
and subdued tropes of standard coffee shop marketing. Instead, it necessitates a visual and 
interactive paradigm that merges extreme sports energy with premium lifestyle aesthetics.1 
This report outlines an exhaustive architectural and implementation strategy for constructing 
the Caffenaline portfolio website. The required functionality involves a highly orchestrated 
sequence of 3D animations, physics simulations, and custom shader effects that respond 
dynamically to user scrolling. The narrative arc of the website begins with an intricate, 
physics-driven simulation of a spoon stirring coffee within a meticulously textured cup. As the 
user initiates a scroll event, the experience transitions into a surreal, gravity-defying sequence 
where the liquid extracts itself into an autonomous fluid sphere. This sphere subsequently 
navigates into a larger vessel, triggering a seamless, shader-driven morphing sequence that 
transforms the visual and physical properties of the liquid through various coffee permutations, 
from a dense espresso to a frothy latte, a rich cappuccino, a chocolate-infused mocha, and 
finally, a dense hot chocolate. 
To achieve this level of cinematic storytelling, the architecture relies on a synthesis of the most 
advanced frontend libraries available, specifically integrating React Three Fiber for declarative 
3D scene management, GSAP with ScrollTrigger for deterministic animation sequencing, Rapier 
for high-performance physics computation, and custom GLSL shaders for fluid morphing and 
hover reveals.3 The methodology detailed within this document provides a comprehensive 
roadmap for engineering this experience, ensuring absolute physical realism, seamless 
transitions, and optimized performance across modern browsers. 
2. The Vibe Coding Framework and Autonomous 

Architectural Setup 
The construction of a production-grade, highly interactive 3D web application requires a 
rigorous development framework to manage the inherent complexity of synchronizing 
Document Object Model (DOM) elements with a WebGL context. The overarching 
development paradigm employed for this project is "Vibe Coding," a modern workflow that 
heavily integrates autonomous artificial intelligence agents to accelerate boilerplate generation, 
user interface (UI) component creation, and complex mathematical logic formulation.5 
However, to prevent the rapid accumulation of technical debt, this methodology must be 
tightly constrained by strict architectural standards and engineering best practices.5 
2.1 Technology Stack and Reconciliation 
The foundation of the project relies on a carefully selected technology stack that prioritizes 
type safety, deterministic state management, and optimized rendering loops. 
●​ Application Framework: The architecture is built upon Next.js to handle routing, 
server-side rendering (SSR), and static site generation (SSG).5 Next.js provides the optimal 
delivery mechanism for the initial HTML payload, ensuring that the heavy 3D assets are 
loaded efficiently. 
●​ 3D Rendering Engine: For the 3D rendering context, React Three Fiber (R3F) operates as a 
custom React reconciler for Three.js.3 R3F allows 3D objects, lights, and cameras to be 
expressed as declarative components within the standard React component tree, 
facilitating the seamless passing of props and state between the 2D DOM and the 3D 
canvas.3 
●​ Animation Orchestration: The GreenSock Animation Platform (GSAP), specifically its 
ScrollTrigger and Flip plugins, handles all timeline-based animations and scroll-linked 
sequencing.7 
●​ Physics Engine: The Rapier physics engine, compiled to WebAssembly (WASM), provides 
deterministic rigid body and kinematic simulations required for the fluid and stirring 
mechanics.8 
●​ Smooth Scrolling: The Lenis library intercepts native browser scrolling, applying linear 
interpolation to provide a buttery-smooth scrolling experience that ensures 3D animations 
tied to the scroll position do not jitter.3 
2.2 Schema-First AI Integration via Model Context Protocol 
The Vibe Coding methodology mandates a schema-first approach.5 Before any frontend logic 
is generated, the underlying data structures representing the menu items, 3D asset paths, 
shader uniforms, and animation waypoints must be strictly defined using TypeScript interfaces. 
This guarantees that all subsequent code generation adheres to a unified data model, 
eliminating runtime errors associated with undefined properties during complex animation 

sequences.5 
To initialize the development environment, the workflow utilizes the Model Context Protocol 
(MCP) to bridge the primary development environment with external design systems.5 The 
integration of frameworks like Antigravity with the Stitch API provides the system with 
high-fidelity design capabilities, ensuring that all generated UI components adhere to strict 
aesthetic guidelines.5 
The execution begins with a highly specific "Master Prompt" that delegates the construction of 
the user interface, the deployment of the smooth scrolling architecture, and the instantiation of 
the 3D canvas.5 Generative UI design and high-level architectural planning are processed 
through models optimized for creative reasoning (e.g., Gemini), while the complex matrix 
mathematics, Rapier physics engine configuration, and GLSL shader programming are 
delegated to models specifically trained on advanced logical and mathematical operations 
(e.g., Claude 3.5/4).5 
2.3 State Management Synchronization 
Bridging the React DOM state with the React Three Fiber rendering loop requires a state 
manager that does not trigger unnecessary re-renders of the entire component tree. The 
architecture mandates the use of Zustand, a minimal and highly performant state manager.5 
Zustand allows the 3D components to subscribe to specific state slices (e.g., the current scroll 
progress, the active coffee menu item, or the global hover state) and update their respective 
Three.js objects directly within the useFrame hook, bypassing the React reconciliation process 
for maximum performance.10

4. The Entrance Reveal and Immersive Preloading 
Sequence 
The initial moments of a user's interaction with the Caffenaline website must immediately 
establish the technical superiority and the energetic tone of the brand. Given the heavy 
payload of high-fidelity 3D models (the cups, the spoon), PBR (Physically Based Rendering) 
textures, and physics engine WebAssembly binaries, a robust and visually engaging preloading 
sequence is mandatory to prevent a jarring initial experience. 
4.1 Smooth Loaders and Framer Motion 
The loader itself is an immersive 2D animation built using Framer Motion, synchronized 
seamlessly with the DefaultLoadingManager of Three.js.22 Instead of a traditional progress bar, 
the loader utilizes a custom GLSL shader applied to a full-screen quad, generating an 
aggressive, fast-moving fluid distortion effect that mimics a rush of adrenaline.23 
The loader state is managed via React context. As the Three.js useProgress hook reports the 
asset downloading completion, the Framer Motion component orchestrates an exit animation. 
The full-screen fluid shader violently splits along the center and accelerates outward, 
simulating a pair of doors being blasted open, revealing the absolute blackness of the initial 
canvas beneath. 
4.2 Immersive Zoom-In and Masked Text Reveals 
As the final assets compile in the GPU memory, the entrance reveal is triggered. This sequence 
relies on an advanced masked text animation technique coordinated by the GSAP SplitText 
plugin and an overarching GSAP timeline.24 
1.​ Text Splitting: The brand name "CAFFENALINE" is split into individual characters using 
GSAP. Each character is contained within a dynamically generated div featuring an 
overflow: clip mask.24 
2.​ Velocity Reveal: The GSAP timeline animates the translation of these characters along 
the Y-axis from an initial state of complete occlusion (transform: translateY(100%)) to full 
visibility (translateY(0)). This is executed with a custom, high-velocity easing function 
(expo.out) with an aggressive stagger, mimicking a sudden jolt or heartbeat. 
3.​ 3D Material Instantiation: Simultaneously, the 3D canvas fades into view. To ensure 
absolute visual continuity, the entrance of the WebGL elements is managed by altering the 
alphaHash properties of their respective materials, allowing the 3D models to dither and 
dissolve into existence rather than snapping abruptly into the frustum.25 
4.​ Camera Pathing: The Three.js PerspectiveCamera, initially positioned with an extremely 
tight field of view (FOV) directly on the surface of the dark coffee, executes an immersive, 

high-speed zoom-out animation. GSAP animates both the camera's position vector and its 
fov property, sweeping back along a predefined Bezier curve to reveal the full context of 
the initial scene: a picture-perfect, hyper-realistic coffee cup resting in a void, with a 
spoon already in motion. 
5. Scene I: Photorealistic Rendering and High-Fidelity 
Coffee Physics 
The first interactive scene grounds the user in the physical reality of the product. It features a 
meticulously modeled coffee cup containing dark liquid, with a metallic spoon actively stirring 
the contents. The success of this scene hinges entirely on the photorealism of the assets and 
the mathematical accuracy of the physics simulation.26 
5.1 High-Fidelity Texturing Pipeline 
The visual fidelity of the cup and the spoon is achieved through a rigorous PBR pipeline utilizing 
the MeshStandardMaterial within Three.js.28 The models, inherently low-polygon to maintain a 
high framerate (e.g., under 5,000 triangles for the cup), derive their extraordinary detail from a 
suite of 4K texture maps sourced from high-end asset libraries like Poly Haven.27 
The material definition requires the precise orchestration of multiple texture channels: 
●​ Albedo Map: Defines the base color without any baked lighting information.31 
●​ Normal Map: A highly detailed vector map used to simulate microscopic surface 
imperfections, scratches on the spoon, and the slight unevenness of the ceramic glaze.28 
●​ Metalness and Roughness Maps: These dictate the conductive properties of the spoon 
(high metalness, low roughness) versus the ceramic cup (low metalness, varying 
roughness).31 
●​ Ambient Occlusion (AO) Map: Applied to a secondary UV set (uv2), this map calculates 
the deep, realistic shadows where the handle meets the body of the cup, ensuring realistic 
light occlusion.31 
To illuminate these materials realistically, a carefully selected High Dynamic Range Image (HDRI) 
environment map is utilized. This provides image-based lighting (IBL) and realistic reflections 
that react perfectly to the camera's movements, without the computational overhead of 
calculating multiple complex shadow-casting lights.33 
5.2 Rapier Physics Simulation for the Stirring Spoon 
The dynamic movement of the spoon stirring the coffee is not a pre-baked, keyframed 
animation imported from Blender; rather, it is a real-time physics simulation powered by the 
Rapier physics engine.9 Rapier is a high-performance, deterministic physics engine written in 
Rust and compiled to WebAssembly, ensuring that complex rigid body dynamics can be 

calculated within the strict time budget of a 60 frames-per-second render loop.8 
Implementing this simulation requires several precise steps: 
1.​ World Initialization: A RAPIER.World instance is initialized, configured with an accurate 
gravity vector pointing along the negative Y-axis ({ x: 0.0, y: -9.81, z: 0.0 }).9 
2.​ Static Colliders: The coffee cup acts as the static environment. Because a cup is a 
concave shape, simple geometric colliders (like cylinders or bounding boxes) are 
insufficient. Instead, the geometry of the cup is extracted, and its vertices and indices are 
passed to Rapier to construct a precise TriMesh collider 
(RAPIER.ColliderDesc.trimesh(vertices, indices)).9 This ensures the spoon can interact with 
the inner walls of the cup accurately. 
3.​ Kinematic Bodies: The spoon is instantiated as a kinematic rigid body.34 A kinematic body 
is not moved by forces or gravity, but its position is updated programmatically. It still 
exerts physical forces on other dynamic objects in the scene. 
4.​ Mathematical Motion: The rotational stirring motion is driven within the R3F useFrame 
hook. The spoon's kinematic position and rotation are updated along a circular path 
defined by sine and cosine functions tied to the Three.js Clock elapsed time. 
5.3 Vertex Displacement for Fluid Surface Mechanics 
Simulating millions of individual fluid particles for the entire volume of coffee using 
Smoothed-Particle Hydrodynamics (SPH) is computationally prohibitive for a web environment. 
Instead, the liquid surface dynamics are achieved through advanced vertex displacement 
within a custom GLSL vertex shader applied to a high-density plane geometry.35 
The vertex shader receives the exact spatial coordinates of the physical spoon as a uniform 
variable (uniform vec3 uSpoonPosition). By calculating the distance between the spoon's 
position and each vertex of the liquid plane, the shader creates a localized depression and a 
trailing wake.35 
 
OpenGL Shading Language 
 
 
// Conceptual Vertex Shader Logic​
float dist = distance(position.xz, uSpoonPosition.xz);​
float influence = smoothstep(0.5, 0.0, dist);​
float vortex = sin(angle + uTime * 2.0) * influence;​
vec3 newPosition = position;​
newPosition.y -= influence * 0.2 + vortex * 0.1;​
 
This vertex displacement is mathematically combined with a rotating vortex algorithm based on 

the angle from the center of the cup. The result is the unmistakable visual of a vigorously stirred 
liquid reacting accurately to the spoon's physical presence, complete with a central depression 
and swirling surface ripples, all computed efficiently on the GPU. 
6. Parallax Storytelling and Scroll-Linked Cinematic 
Sequencing 
As the user digests the initial scene, the narrative progresses through user-initiated scrolling. 
The orchestration of 3D events tied to the user's scrollbar is entirely managed by GSAP's 
ScrollTrigger plugin.7 Modern storytelling in WebGL requires the seamless integration of DOM 
scrolling mechanisms with the absolute coordinate space of the 3D camera and objects.24 
6.1 Smooth Scrolling and Interpolation 
To achieve a premium, fluid feel, the native browser scrolling is overridden by the Lenis smooth 
scrolling library.3 Lenis applies linear interpolation to the scroll velocity, ensuring that the scroll 
progress values update smoothly regardless of the user's input device (trackpad, mouse wheel, 
or touch). 
The GSAP ScrollTrigger is configured with the scrub property set to a fractional value (e.g., 
scrub: 1).7 This creates a sophisticated "catch-up" effect. When the user stops scrolling, the 3D 
animations do not halt abruptly but instead possess an elegant, physical inertia, taking exactly 
one second to smoothly reach the target state.7 
6.2 Canvas Pinning and Spatial HTML Overlays 
As the menu section approaches the viewport, the DOM container holding the WebGL canvas 
is locked into a fixed position using ScrollTrigger's pin: true configuration.7 This prevents the 
canvas from scrolling out of view, transforming the user's vertical scroll action into a timeline 
scrubber that drives the internal narrative of the 3D scene.7 
Simultaneously, immersive 2D animations overlay the 3D canvas. DOM-based text elements 
representing the menu categories slide into the viewport. Their movements are perfectly 
synchronized with the WebGL camera's motion using shared GSAP timelines.24 The layout 
utilizes a spatial design concept: the HTML text elements act as foreground layers, moving at 
different velocities compared to the 3D camera, thereby creating an intense parallax effect 
against the deep, moving 3D background.37 
7. Scene II: Anti-Gravity Fluid Extraction and 
Volumetric Sphere Generation 
The most visually arresting sequence of the Caffenaline experience occurs as the scroll initiates 

the menu section. The narrative dictates that the dark coffee liquid must defy gravity, rising out 
of the cup and coalescing into a perfectly spherical, floating globule of fluid. 
Morphing standard polygonal geometry from a flat plane (the liquid surface in the cup) into a 
complex, organic sphere is a notoriously difficult problem in computer graphics. Standard 
vertex interpolation fails to capture the chaotic, splitting, merging, and 
surface-tension-breaking nature of real liquids.38 To achieve this gravity-defying extraction with 
absolute photorealism, the architecture abandons standard mesh deformation in favor of 
volumetric fluid rendering techniques. 
There are two viable mathematical paradigms for this effect: the Marching Cubes algorithm or 
Shader-based Raymarching using Signed Distance Functions (SDFs).39

For this specific sequence, Raymarching via SDFs is selected to maximize the visual fluidity of 
the extraction. The fluid forms are defined mathematically within a full-screen fragment shader. 
As the GSAP ScrollTrigger progress advances, the mathematical parameters governing the 
SDFs are animated. The primary fluid mass is represented by a large sdSphere that translates

8. Scene III: Seamless Shader-Driven Liquid Morphing 
As the scroll continues, the floating coffee sphere descends along a bezier path into a massive, 
monolithic coffee cup that serves as the visual anchor for the interactive menu. Once the 
sphere rests within this vessel and flattens into a surface, a highly complex morphing sequence 
initiates, transforming the liquid sequentially through the menu offerings: Espresso, Latte, 
Cappuccino, Mocha, and Hot Chocolate. 
This transformation is not a simple color crossfade or image opacity swap. It requires a 
profound, real-time alteration of the liquid's physical and visual characteristics, including its 
viscosity, foam density, color profiling, subsurface scattering, and surface turbulence. This is 
achieved through a master ShaderMaterial applied to the liquid surface, driven by uniforms 
passed down from the React Three Fiber state.35 
The GSAP scroll progress is mapped to a discrete floating-point uniform, uProgress (ranging 
from 0.0 to 5.0), which dictates the current state of the liquid.24 The fragment and vertex 
shaders utilize the GLSL mix() function extensively to linearly interpolate between the distinct 
visual mathematical states defined for each beverage.42 
8.1 State 0: The Espresso Base 
The sequence begins with the Espresso state. The base color vectors are defined by the deep, 
rich hex codes established in the brand identity (vec3(0.31, 0.23, 0.19), corresponding to 
#4F3C32).14 The surface is assigned a high specularity value, reflecting the sharp, oily nature of 
a pure coffee extraction. A subtle, high-frequency Perlin noise function modulates the normal 
vectors to simulate the microscopic bubbles of the espresso crema.43 The vertex displacement 
is minimal, representing a flat, dense liquid. 
8.2 State 1: The Latte Swirl 
As uProgress shifts from 0.0 to 1.0, the mathematics governing the shader alter drastically. The 
base color interpolates toward a lighter, creamier hue (#B4A6A1).14 More importantly, the 
algorithm introduces complex fluid mixing visuals. A multi-octave noise function combined with 
a rotational matrix (twirl node logic) generates a sprawling, swirling pattern of white and tan 

across the UV coordinates, mimicking the chaotic injection of steamed milk into dark 
espresso.45 The overall specularity is mathematically dampened to simulate the matte finish of 
microfoam.46 
8.3 State 2: The Cappuccino Foam 
The transition to Cappuccino (uProgress 1.0 to 2.0) necessitates a structural change to the 
surface geometry. The vertex shader is re-engaged, using a low-frequency, high-amplitude 
noise function to displace the vertices upward along their normal vectors, simulating a thick, 
uneven layer of dense foam resting on the liquid surface.35 
To optimize this effect, the noise is not generated procedurally via complex mathematical 
operations every frame, which would degrade performance on mobile GPUs.43 Instead, a 
pre-rendered, high-resolution Perlin noise texture is loaded via TextureLoader and sampled by 
the shader to drive both the vertex displacement (height) and the fragment color variations 
(lightness at peaks, shadows in valleys).43 
8.4 State 3: The Mocha Drizzle 
Proceeding to the Mocha state (uProgress 2.0 to 3.0), the shader logic introduces a secondary, 
highly viscous fluid dynamic. The base color shifts back toward a warmer brown (#967969).15 A 
new procedural layer is introduced into the fragment calculation using 2D Signed Distance 
Functions.36 This SDF generates dark, sharp-edged ribbon patterns that stretch and warp 
across the surface over time, flawlessly replicating the visual of rich chocolate syrup being 
drizzled and subsequently dissolving into the foam layer.45 
8.5 State 4: The Hot Chocolate Density 
Finally, the morph completes at the Hot Chocolate state (uProgress 3.0 to 4.0). The dramatic 
vertex displacement of the cappuccino foam is smoothed out via interpolation, returning to a 
flatter, more homogenous liquid surface. The diffuse color deepens significantly. Crucially, the 
shader calculates a high level of subsurface scattering. This mathematical approximation allows 
ambient light to penetrate the surface and scatter internally, giving the hot chocolate a thick, 
dense, and opaque visual weight that completely differs from the highly reflective, oily 
properties of the initial espresso state. 
Throughout this entire scroll-linked sequence, the transitions are algorithmically seamless. The 
interpolation matrices ensure that colors do not simply snap, but actively swirl, displace, and 
mix into one another, providing a deeply satisfying, continuous visual evolution that keeps the 
user fiercely engaged with the menu content. 
9. Interactive Enhancements: 3D Hover Reveal 

Architecture 
To elevate the portfolio beyond a passive viewing experience, the user interface must react 
violently and beautifully to direct user input. While the scroll acts as the macro-controller for 
the narrative, mouse interactions serve as micro-controllers, providing immediate, 
high-adrenaline feedback. The hallmark of a trend-setting 2026 frontend architecture is the 3D 
hover reveal animation, which bridges the gap between the 2D DOM menu elements and the 
3D WebGL context.24 
9.1 Raycasting and Event Delegation 
As the user navigates the DOM-based menu text (rendered in the aggressive, variable 
sans-serif typography), their mouse movements are tracked. The mouse coordinates are 
normalized to a -1.0 to 1.0 scale. A THREE.Raycaster is projected from the 2D cursor position 
into the 3D space, intersecting with invisible proxy planes positioned directly behind the HTML 
text elements.10 
9.2 Custom Transition Shaders 
When a hover event is registered via the raycaster, a bespoke React Three Fiber component is 
triggered.6 This component utilizes a custom shaderMaterial specifically designed for 
aggressive image transition effects.48 
The shader takes three primary textures as uniforms: 
1.​ uTexture1: The base state (e.g., a high-contrast, moody rendering of raw coffee beans). 
2.​ uTexture2: The hover state (a high-octane, dopamine-colored photograph of the finished 
beverage in an extreme sports setting). 
3.​ uDispMap: A displacement map consisting of turbulent, high-contrast grayscale noise.49 
The transition between these two textures is not a standard, linear opacity fade. Instead, as the 
hover state activates, a uniform value (uHoverProgress) is animated smoothly from 0.0 to 1.0 
via a Framer Motion spring physics curve. Inside the fragment shader, this progress value drives 
a complex distortion algorithm.22 
 
OpenGL Shading Language 
 
 
// Conceptual Hover Transition Fragment Shader​
vec4 disp = texture2D(uDispMap, vUv);​
vec2 distortedUV = vUv + disp.rg * uHoverProgress * 0.5;​
​

vec4 color1 = texture2D(uTexture1, vUv + (1.0 - uHoverProgress) * disp.rg);​
vec4 color2 = texture2D(uTexture2, distortedUV);​
​
gl_FragColor = mix(color1, color2, uHoverProgress);​
 
The pixels of the base image are violently warped and displaced along the vectors defined by 
the noise map, visually tearing the first image apart to reveal the second image beneath it.49 
This effect, executed entirely on the GPU, happens instantaneously and with absolute fluidity. 
The aggressive, tearing transition perfectly aligns with the "adrenaline rush" brand identity, 
turning a simple UI hover state into a visceral, satisfying visual explosion. Furthermore, 
post-processing effects, such as a localized chromatic aberration and selective bloom, are 
applied specifically to the boundaries of the image during the transition, adding a layer of 
cinematic polish that defines top-tier frontend engineering.23 
10. Performance Optimization and GPU Resource 
Management 
Deploying a web application featuring physics engines, raymarching, and multiple 
high-resolution textures requires stringent performance optimization to ensure the experience 
remains fluid (60 frames per second) across diverse hardware profiles, particularly mobile 
devices. 
The architecture employs several critical optimization strategies: 
1.​ Texture Compression: All 4K PBR textures are compressed into hardware-optimized 
formats (e.g., KTX2 or WebP) to drastically reduce GPU memory consumption and VRAM 
bandwidth during the scene loading phase.28 
2.​ Instanced Rendering: If the scene requires multiple repeating objects (e.g., flying coffee 
beans during the extraction phase), THREE.InstancedMesh is utilized. This allows the GPU 
to render thousands of identical geometries in a single draw call, altering only their 
position, rotation, and scale matrices via the Rapier physics engine.51 
3.​ Geometry Pooling and Disposal: To prevent memory leaks during the long scrolling 
sequences, WebGL geometries and materials that fall outside the camera's frustum are 
systematically disposed of using Three.js's .dispose() methods. 
4.​ DPR Scaling: The renderer's Device Pixel Ratio (DPR) is dynamically capped. While 
high-end desktop displays may support a DPR of 2 or 3, locking the maximum DPR to 1.5 
ensures that the heavy fragment shaders (particularly the Raymarching fluid sphere) do 
not overwhelm the GPU by calculating too many pixels.

synthesis of distinct engineering disciplines. By strictly adhering to the schema-first Vibe

The visual identity successfully weaponizes the aesthetic tropes of extreme sports and the
